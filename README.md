## 约定

- 文案只做原理与算法演示；页脚固定两行：模拟数据声明 + 「系统不判定人员状态」。
- 颜色语义：青 `#22D3EE` 主色 / 橙 `#FB923C` 逆流 / 粉 `#FF6B8A` 原始信号 / 琥珀 `#FFC24B` 阈值 / 绿 `#34D399` 合格。
- 时长条长度按 90× 放大差值显示（真实两条只差 0.15%），面板脚注已注明。
- 每节内容都登记在 `config.js`：`SECTIONS[i].built = true`，并把 `T_BUILT` 推到该节结束（本轮一次补齐 09 / 10，`T_BUILT` 到 82.00）。
- 版面节奏（06–10）：06 / 08 是**左右分屏**（左青域=判定、右橙红域=预警，中间缝一条竖线）；07 是**独立全屏**，这时 `gateMask()` 压掉章节卡、底部两栏与分屏底，门控独占画面。09（链 + 三模块 + 指标卡）与 10（24 h 四拍）各自整屏，章节卡自动上抬 40 px 让位。
- 09 的通信模块只在「需上报」时点亮；链上的闸门站恒灰（`.mNode.dim`），人员侧不参与，也不冒充告警。推近 ×5 / 拉回 ×0.6 用 `SEC['09'].zoom` 出读数，画面缩放按可读比例收敛（`vis`），避免链条被裁成一个大字。
- 10 的「05 反向播放」把 `SEC['10'].rev` 的内容时间 `tm`（41.10 → 33.55）倒着喂给 `stepBus()`，同一套动作整体回退，不另写一套动画。
- 收尾：`#endLine` 固定在屏幕中下方（80.46 起淡入）；判定卡放大时底部两栏先让位（`endGone`），避免压字。
- 任何区域都不允许静止：分屏底 / 中缝有呼吸，闸门有微光，分级灯持续微放大，代码逐行点亮，脚注延迟淡入。
- 相机：`SHOTS` 的 key 为 `[t, az, el, dist, tx, ty]`；漂移以「有界噪声差值 + 恒定爬行」叠在脚本机位上，缓速窗口只放慢漂移。
- 指令 / 代码面板逐条对应十节：页眉行号写成 `03/10 · 01/04`（本节序号 / 十节 · 第几条），当前条加 `.on`（指令青、代码琥珀），切节时整块重排。
- 03 的迭代片段（`BL.ITER`）是**时间驱动的预编排**，不是一次性动画：写错 → 报错 → 只改 1 行 → 重跑 → 画面修正，暂停与回拖都会原样重放。
- 导出视频（`#btnExp`）：WebCodecs `VideoEncoder` 逐帧编码 **H.264（avc1.640028，关键帧每 2 s）→ `mp4.js` 自己封 MP4**（faststart：moov 在 mdat 前，`stts` 恒定 1000/24000 → 严格 24 fps，`stss` 关键帧索引）。**成片时长严格 = 节次区间**（整片 9.00–82.00 → 1752 帧 / 73.000 s / 1280×720），且是剪辑软件可直接拖入的 MP4/H.264，可逐帧切、可对齐时间码。选 MP4 而不是 WebM：VP9/WebM 在部分播放器与剪辑软件里会被判为「损坏」，且旧实现缺 Cues 索引。
  导出时主循环空转、相机底噪冻结，导出器独占渲染（`seek` 只推进 3D 内容层，不重绘 DOM HUD），整片 1752 帧约 **14 s**（5× 实时）。回退链：H.264 不可用 → VP9/VP8 + `webm.js` → `MediaRecorder`（最后一级的帧时间戳跟随浏览器时钟，无法保证时长）。
  画面为 3D 画面 + 烧录角标（节次 / 时间码 / 「模拟数据」声明），DOM HUD 不参与合成。口播与音频：无。
  工作区里已导出一份整片：`blander_B_9.0-82.0.mp4`（50.4 MB，73.000 s，1280×720，24 fps）。
